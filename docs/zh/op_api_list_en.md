# Operator APIs (aclnn)

## Instructions

To facilitate the calling of operators, a set of C-based APIs (prefixed with `aclnn`) is provided, eliminating the need for IR (Intermediate Representation) definitions. This approach enables efficient model construction and application development, and is referred to as single operator API calling, or simply `aclnn` calling.

When calling the operator API, it is necessary to reference the dependent header files and library files. Generally, the header files are located by default in `${INSTALL_DIR}/include/aclnnop`, and the library files are located by default in `${INSTALL_DIR}/lib64`. The specific files are as follows:

- Dependent header files: ① Method 1 (recommended): Include the general operator header file `aclnn_ops_${ops_project}.h`. ② Method 2: Include the single operator API header file `aclnn_*.h` as needed.
- Dependent library files: Reference the operator library file **libopapi\_\$\{ops\_project\}.so** as needed.

Here, `${INSTALL_DIR}` represents the file path after CANN installation; `\$\{ops\_project\}` denotes the operator repository (for example, math, nn, cv, transformer). Configure it as the actual operator repository name.

## API List

> **Deterministic Computation**:
>
> - Configuration: Due to differences in CANN or NPU models, it may not be guaranteed that the same operator will produce consistent results across multiple runs. Under the same conditions (platform, device, version number, and other random parameters), some operator interfaces can enable deterministic algorithms through `aclrtCtxSetSysParamOpt` (refer to [acl API (C)](https://www.hiascend.com/document/detail/en/canncommercial/850/API/appdevgapi/aclcppdevg_03_0004.html)) to ensure consistent results across multiple runs.
> - Performance: Using deterministic computation for the same operator is generally slower than non-deterministic computation, which may result in a decrease in the performance of a single model run. However, in scenarios such as experiments, debugging, and testing, where it is necessary to ensure consistent results across multiple runs to identify issues, deterministic computation can improve efficiency.
> - Threads: The deterministic state can only be set once within the same thread, and the last valid setting will take precedence if set multiple times. A valid setting refers to the actual execution of an operator task after setting the deterministic state. If only set without operator task execution, it means the deterministic variable is enabled but not dispatched to the operator, thus the operator will not be executed.
>   Solution: It is not recommended to set determinism multiple times in a single thread. This issue exists both when the binary is enabled and disabled, and it will be resolved in future versions.
