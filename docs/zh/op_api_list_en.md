# Operator APIs (aclnn)

## Instruction

To make it easier to call operators, a set of C-based APIs (with the **aclnn** prefix) are provided. You do not need to provide the Intermediate Representation (IR) definition to facilitate efficient model and application development. This method is called single-operator API calling, or aclnn calling for short.

When calling an operator API, you need to reference the required header files and library files. Generally, the header files are stored in `${INSTALL_DIR}/include/aclnnop` by default, and the library files are stored in `${INSTALL_DIR}/lib64` by default. The specific files are as follows:

- Header files: 1. (Recommended) Method 1: Reference the operator header file aclnn\_ops\_\$\{ops_project\}.h. 2. Method 2: Reference the single-operator API header file aclnn\_\*.h as required.
- Library files: Reference the operator library file libopapi\_\$\{ops_project\}.so as required.

*${INSTALL_DIR}* indicates the file path after CANN is installed. *${ops_project}* indicates an operator repository (such as math, nn, cv, and transformer). Set this parameter to the actual operator repository name.

## APIs

> **Deterministic computation:**
>
> - Configuration: Due to different CANN or NPU models, multiple runs of the same operator may have different results. Under the same conditions (platform, device, version number, and other random parameters), you can enable the deterministic algorithm by calling aclrtCtxSetSysParamOpt, see to ensure that the results of running the same operator for multiple times are consistent.
> - Performance: An operator using deterministic computing is usually slower than using non-deterministic computation. Therefore, the performance of a single model run may deteriorate. However, in scenarios such as experiments and debugging, where the same results must be obtained upon multiple runs for fault locating, deterministic computation can improve efficiency.
> - Threads: The deterministic status can be set only once in the same thread. If the deterministic status is set multiple times, the last valid setting is used. A valid setting refers to a deterministic status that has been used to deliver an operator task. If no operator task is delivered, only the deterministic variable is enabled but it is not delivered to the operator. As a result, the operator is not executed.
>   Solution: You are not advised to set the deterministic property multiple times for a thread. This problem exists no matter whether the binary function is enabled or not. It will be solved in later versions.
