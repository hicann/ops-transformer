## Function

- Description: Performs single-path rotary position encoding computation. Compared with [aclnnRotaryPositionEmbedding](aclnnRotaryPositionEmbedding_en.md), this API adds the input parameter rotate, which improves performance in recommendation use cases by inputting the rotation encoding matrix. Choose an appropriate API based on the actual situation.

- Recommended Scenarios for rotate
  - interleave mode, and B *N* S > 28800.
  - half mode is recommended only in the following scenario: when the input matrix x needs to be split into multiple parts along the last dimension, and each part requires a call to the aclnnRotaryPositionEmbedding API for rotary position encoding computation, you can construct a rotary encoding matrix to achieve performance gains with a single call. For example, when the layout of x is BSND and needs to be split into three parts:
     x is split into 3 parts: $x = [x1|x2|x3]_{(dim=4)} ∈ R^{B×S×N×D}, x1 ∈ R^{B×S×N×D1},x2 ∈ R^{B×S×N×D2},x3 ∈ R^{B×S×N×D3},where D = D1 + D2 + D3$. A rotate matrix can be constructed so that the rotary position encoding computation on x is completed with a single call to the aclnnRotaryPositionEmbeddingV2 API. The rotate matrix is constructed as follows:

     $$rotate = diag(rotate1, rotate2, rotate3) = \begin{pmatrix}rotate1&0&0\\0&rotate2&0\\0&0&rotate3\\\end{pmatrix}$$

     where rotate1, rotate2, and rotate3 are the rotary encoding matrices of x1, x2, and x3, respectively. For how to construct a single rotary matrix, see the Example section.

- Formula:

  - x1 is INT8, x2 is INT8, x1Scale is FLOAT32, and x2Scale is FLOAT32.

    - Without the rotate parameter (recommended for half mode 1D):

      (1) half mode (mode equals 0):

      $$
      x1 = x[..., : x.shape[-1] // 2]
      $$

      $$
      x2 = x[..., x.shape[-1] // 2 :]
      $$

      $$
      x\_rotate = torch.cat((-x2, x1), dim=-1)
      $$

      $$
      y = x * cos + x\_rotate * sin
      $$

      (2) interleave mode (mode equals 1):

      $$
      x1 = x[..., ::2].view(-1, 1)
      $$

      $$
      x2 = x[..., 1::2].view(-1, 1)
      $$

      $$
      x\_rotate = torch.cat((-x2, x1), dim=-1).view(x.shape[0], x.shape[1], x.shape[2], x.shape[3])
      $$

      $$
      y = x * cos + x\_rotate * sin
      $$

    - When the rotate parameter is passed (the rotate matrix is generated by the developer; see the generation section in the Example for reference):

      $$
      x\_rotate = x  @ rotate
      $$

      $$
      y = x * cos + x\_rotate * sin
      $$

## Constraints

<!-- npu="A3,910b" id10 -->
- x1 is INT8, x2 is INT8, x1Scale is FLOAT32, and x2Scale is FLOAT32.

  The input tensor x supports BNSD, BSND, SBND, and TND layouts.
  The D dimension size of the input tensors x, cos, sin and the output tensor y must be the same, must satisfy D < 896, and must be a multiple of 2.
  The shapes of the input tensor x and the output tensor y must be exactly the same.
  The shapes of the input tensors cos and sin must be exactly the same.

  - Half mode:
    - B, N < 1000;
    - When x is BNSD, cos and sin support 11SD, B1SD, and BNSD.
      - When (D/2) % (32/inputDtypeSize) == 0, B*N <= S* 8 must be satisfied.
      - When (D/2) % (32/inputDtypeSize) != 0, B*N*2 <= (S + coreNum -1) / coreNum or D >= 80 must be satisfied.
    - When x is BSND, cos and sin support 1S1D, BS1D, and BSND.
    - When x is SBND, cos and sin support S11D, SB1D, and SBND.
    - When x is TND, cos and sin support T1D and TND.
  - Interleave mode:
    - B * N < 1000 (N < 1000 when x is TND).
    - When x is in BNSD format, cos and sin support 11SD.
    - When x is in BSND format, cos and sin support 1S1D.
    - When x is in SBND format, cos and sin support S11D.
    - When x is TND, cos and sin support T1D.
<!-- end id10 -->
<!-- npu="950" id11 -->
- <term>Ascend 950PR&950DT products</term>:

  Input tensor x supports the BNSD, BSND, SBND, and TND layouts. The rotate parameter currently supports only a null pointer, and passing a valid tensor causes an error. The shape constraints of the parameters are described as follows:
  - The last dimension of input tensors x, cos, sin, and output tensor y must be the same size and less than or equal to 1024. For half, interleave, and interleave-half modes, the last dimension must be divisible by 2. For quarter mode, the last dimension must be divisible by 4.
  - The shapes of input tensor x and output tensor y must be completely identical.
  - The shapes of input tensors cos and sin must be exactly the same. The shapes of cos and sin must satisfy the [broadcast relationship](../../../docs/en/context/broadcast_relationship.md) with x, and the shape after broadcasting must be the same as the shape of x.
  - When x is TND, cos and sin support T1D and TND.

  import torch
  import torch_npu

  def get_interleave_matrix(n):
      matrix = torch.zeros(n, n, dtype=torch.bfloat16)
      for i in range(0, n, 2):
          matrix[i + 0, i + 1] = 1
          matrix[i + 1, i + 0] = -1
      return matrix

  def get_half_matrix(n):
      matrix = torch.zeros(n, n, dtype=torch.bfloat16)
      half = n // 2
      matrix[:half, half:] = torch.eye(half)
      matrix[half:, :half] = -torch.eye(half)
      return matrix

  def compose_2matrix(A, B):
      total_rows = A.size(0) + B.size(0)
      total_cols = A.size(1) + B.size(1)
      result = torch.zeros(total_rows, total_cols, dtype=torch.bfloat16)
      result[:A.size(0), :A.size(1)] = A
      b_row_start = A.size(0)
      b_col_start = A.size(1)
      result[b_row_start:b_row_start + B.size(0),
             b_col_start:b_col_start + B.size(1)] = B
      return result

  def main():
      # interleave
      inter_mat_128 = get_interleave_matrix(128)
      inter_mat_64 = get_interleave_matrix(64)
      # interleave 2D
      inter_mat_128_64 = compose_2matrix(inter_mat_128, inter_mat_64)

      x = torch.rand(2, 2, 5, 128).npu()
      r1 = torch.rand(1, 2, 1, 128).npu()
      r2 = torch.rand(1, 2, 1, 128).npu()
      out = torch_npu.npu_rotary_mul(x, r1, r2, "interleave", inter_mat_128.npu())
