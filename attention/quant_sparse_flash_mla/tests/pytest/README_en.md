# quant_sparse_flash_mla Operator Test Framework

English | [简体中文](./README.md)

## Description

The framework implements functional verification of the quant_sparse_flash_mla operator based on the pytest test framework:

- **CPU side**: Replicates the operator logic to generate golden data

- **NPU side**: Calls the operator directly and in graph mode through torch_npu to obtain actual output data
- **Accuracy comparison**: Compares CPU and NPU results to verify operator functions

## Current Implementation Scope

### Parameter Restrictions

- **Data formats**:
    - **layout_q**: BSND, TND
    - **layout_kv**: BSND, TND, PA_BBND

### Environment Configuration

#### Prerequisites

1. Confirm that torch_npu is the latest version.

#### Custom Package Invocation

Invocation through the custom package is supported.

## File Structure

### pytest File Structure Description

- test_run.sh                                               # Case execution script
- quant_sparse_flash_mla_golden.py                   # Operator input parameter processing and CPU-side golden implementation
- result_compare_method.py                                  # Accuracy comparison script between CPU golden data and NPU results
- pytest.ini                                                # Defines test markers

Single-case testing:

- test_quant_sparse_flash_mla_single.py              # Main program for running a single pytest test case
- quant_sparse_flash_mla_paramset.py                 # Input parameter configuration for single cases

Batch testing:

- test_quant_sparse_flash_mla_batch.py               # Main program for batch case testing; reads PT cases, obtains NPU output, and saves results to an Excel file
- ./batch/test_quant_sparse_flash_mla_pt_save.py     # Reads the Excel table and generates case PT files in batch
- ./batch/quant_sparse_flash_mla_process.py          # Calls the operator API to obtain NPU output

## Usage

Run the commands in the pytest folder:

### Running Test Cases

#### Single-Case Testing

1. Manually configure the parameters in quant_sparse_flash_mla_paramset.py.

2. Run the commands:

``` bash
bash test_run.sh single
```

#### Batch Testing

Three batch testing modes are supported. Options can specify the Excel file, sheet name, and PT save directory in all modes:

| Command | Function |
|------|------|
| `batch_save` | Reads cases from the Excel file → golden computation → saves PT files |
| `batch_exec` | Reads PT files → NPU test (`batch_save` is required first) |
| `batch` | Full flow: `batch_save` + `batch_exec`; PT files are cleaned up after completion by default |

##### Options

| Option | Description | Default Value | Applicable Commands |
|------|------|--------|---------|
| `--excel <path>` | Specifies the Excel file path | `./excel/example.xlsx` | batch_save / batch_exec / batch |
| `--sheet <name>` | Specifies the Excel sheet name | `decode` | batch_save / batch |
| `--pt-dir <directory>` | Specifies the PT file save/read directory | `qsmla_testcase` | batch_save / batch_exec / batch |
| `--keep-pt` | Keeps PT files after execution completes | Cleaned up by default | batch only |

##### Usage Examples

``` bash
# batch_save: generates only PT files
bash test_run.sh batch_save
bash test_run.sh batch_save --excel my.xlsx --sheet prefill --pt-dir my_pt

# batch_exec: runs only the NPU test (PT files must be generated by batch_save first)
bash test_run.sh batch_exec
bash test_run.sh batch_exec --pt-dir my_pt

# batch: full flow (PT files are cleaned up by default)
bash test_run.sh batch

# batch: full flow, keeps PT files
bash test_run.sh batch --keep-pt

# batch: full flow, customizes all parameters
bash test_run.sh batch --excel my.xlsx --sheet prefill --pt-dir my_pt --keep-pt
```
