## Function Description

- Operator function:

  The `MixedQuantSparseFlashMla` operator performs MLA (Multi-head Latent Attention) computation in quantization and sparsity scenarios. It supports three types of attention computation scenarios: SWA (Sliding Window Attention), CSA (Compressed Sparse Attention), and HCA (Heavily Compressed Attention). Different from `SparseFlashMla`, this operator supports per-token-group quantized KV input. The three typical scenarios of this operator are as follows:

  - **SWA (Sliding Window Attention)**: Only `ori_kv` is passed in, and sliding window attention is performed on the original KV.
  - **CSA (Compressed Sparse Attention)**: `ori_kv`, `cmp_kv`, and `cmp_sparse_indices` are passed in, and attention is performed on both the original KV window and the compressed KV selected by topK.
  - **HCA (Heavily Compressed Attention)**: `ori_kv` and `cmp_kv` are passed in, and attention is performed on both the original KV window and the continuous compressed KV segments.

  The invocation requires the task list `metadata` generated by `MixedQuantSparseFlashMlaMetadata`, which is generated before the main operator is executed. In the current version, this `metadata` must be passed to the main operator. The typical calling process is as follows:

  1. Prepare the corresponding inputs such as `q`, `ori_kv`, and `cmp_kv` based on the calling scenario.
  2. Call `MixedQuantSparseFlashMlaMetadata` to generate `metadata`, which is used as an input parameter of `MixedQuantSparseFlashMla`.
  3. Call `MixedQuantSparseFlashMla` and pass the `metadata` obtained in the previous step to the main operator to generate the computation result.

- Computation formula:

  `MixedQuantSparseFlashMla` uses MLA to compute sparse attention on inputs where Key and Value share the same data. The principle is to selectively compress and quantize the input KV, and then obtain the attention weights by applying Softmax to the computation result of the Query and the concatenated KV.

  The MLA computation formula is generally defined as follows, where $\tilde{K}=\tilde{V}$ is the KV that actually participates in the computation, controlled by the input parameters and composed of the sliding window part of `ori_kv` and the compressed part of `cmp_kv`. The range of the KV that actually participates in the computation is determined by `cmp_ratio`, `ori_mask_mode`, `cmp_mask_mode`, `ori_win_left`, `ori_win_right`, and `cmp_sparse_indices`.

    $$
    O = \text{softmax}(Q@\tilde{K}^T \cdot \text{softmax\_scale})@\tilde{V}
    $$

- This API is used in inference scenarios.
- This API supports the aclgraph mode.
- This API supports batch consistency.
- This API currently supports three computation scenarios: in the SWA (Sliding Window Attention) scenario, only `ori_kv` is passed in; in the CSA (Compressed Sparse Attention) scenario, `ori_kv`, `cmp_kv`, and `cmp_sparse_indices` are passed in; in the HCA (Heavily Compressed Attention) scenario, `ori_kv` and `cmp_kv` are passed in.

- The general specification constraints are as follows:
  - kv_n supports only 1, and q_d supports only 512. The kv_d of `ori_kv` and `cmp_kv` is concatenated from nope, rope, scale, and padding. For details, see `quant_mode`.
  - `cmp_ratio` indicates the compression ratio of `cmp_kv` relative to the pre-compression KV length. When only `ori_kv` is passed in, `cmp_ratio` does not participate in the compressed KV computation and must remain 1. Supports 1 to 128.
  - `ori_mask_mode` supports 0, 3, and 4, and `cmp_mask_mode` supports 0 and 3. `ori_win_left` and `ori_win_right` support -1 or non-negative values, where -1 indicates that the corresponding direction is unrestricted. Only when `ori_mask_mode` is 4, `ori_win_left` and `ori_win_right` can be >= 0.
  - `rope_head_dim` supports only 64.
  - The combinations of `layout_q` and `layout_kv` support only "BSND"/"BSND", "TND"/"TND", "BSND"/"PA_BBND", and "TND"/"PA_BBND". In non-PA_BBND scenarios, `layout_q` and `layout_kv` must be the same. In PA_BBND scenarios, `block_size` supports 1 to 1024.
- When `layout_q` is TND, the function usage restrictions are as follows:
  - The shape of `q` must be [q_t, q_n, q_d].
  - The shape of `ori_sparse_indices` must be [q_t, kv_n, ori_kv_k].
  - The shape of `cmp_sparse_indices` must be [q_t, kv_n, cmp_kv_k].
  - `cu_seqlens_q` must be passed in. The input dimension is b+1, and the value of each element indicates the total number of tokens in the current batch and all previous batches, that is, the prefix sum. Therefore, the value of each subsequent element must be >= the value of the previous element, and the first element must be 0.
- When `layout_q` is BSND, the function usage restrictions are as follows:
  - The shape of `q` must be [b, q_s, q_n, q_d].
  - The shape of `cmp_sparse_indices` must be [b, q_s, kv_n, ori_kv_k].
  - The shape of `cmp_sparse_indices` must be [b, q_s, kv_n, cmp_kv_k].
- In the PageAttention scenario, the function usage restrictions are as follows:
  - The shapes of `ori_kv` and `cmp_kv` are [ori_kv_block_nums, ori_kv_block_size, kv_n, kv_d] and [cmp_kv_block_nums, cmp_kv_block_size, kv_n, kv_d] respectively, where ori_kv_block_nums and cmp_kv_block_nums are the numbers of blocks in the PagedAttention scenario, and ori_kv_block_size and cmp_kv_block_size are the numbers of tokens in a block, ranging from 1 to 1024.
  - The shapes of `ori_block_table` and `cmp_block_table` are 2D, where the length of the first dimension is b, and the length of the second dimension is not smaller than the number of blocks corresponding to the maximum ori_kv_s and cmp_kv_s across all batches, that is, ori_kv_s_max / ori_kv_block_size and cmp_kv_s_max / cmp_kv_block_size rounded up.
- `metadata` is the core partitioning result actually used by the operator. Currently, this parameter is mandatory, and its shape size is fixed to [2048].
- `layout_kv` supports "BSND", "TND", and "PA_BBND" as inputs, and must satisfy the preceding combination constraints of `layout_q` and `layout_kv`.
  - When the input is PA_BBND, `seqused_ori_kv` and `ori_block_table` must be passed in. When the input is BSND, `seqused_ori_kv` can be used to express the valid length of `ori_kv` in each batch. When the input is TND, the valid length of `ori_kv` is expressed by `cu_seqlens_ori_kv`.
  - When the input is BSND, the layouts of both `ori_kv` and `cmp_kv` must be BSND. The shape of ori_kv is [b, ori_kv_s, kv_n, kv_d], and the shape of cmp_kv is [b, cmp_kv_s, kv_n, kv_d].
  - When the input is TND, `cu_seqlens_ori_kv` must be passed in. If `cmp_kv` exists, `cu_seqlens_cmp_kv` must also be passed in.
- When `return_softmax_lse` is False, a placeholder Tensor is returned. When it is True, the log-sum-exp result of softmax is returned.
- Reserved inputs such as `ori_topk_length` and `cmp_topk_length` may not be passed in or may be passed in as empty Tensors. Other passed-in Tensors cannot be empty.
- `seqused_cmp_kv` is an optional input for all `layout_kv` values. When explicitly passed in, it is used to overwrite the logical valid length on the cmp side. When not passed in, it is derived from the `cmp_kv` shape, `cu_seqlens_cmp_kv`, or the semantics related to the PA block table.
- `cmp_residual_kv` is an optional input parameter of the operator. After it is passed in, it is used to restore the pre-compression KV length used by the mask on the cmp side according to `cmp_len * cmp_ratio + residual`, where `cmp_len` preferentially comes from the explicitly passed-in `seqused_cmp_kv`.
