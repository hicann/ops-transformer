# QMLA FP8 优化记录（2026-09-21）

## 结论与保留版本

默认 case 最好的已验证结果为 **268.571111 μs，MFU 84.178138%**。
原始基线为 338.193722 μs、66.848716%，延迟下降约 20.59%。
**85% 目标尚未达到**；按相同 FLOPs 和峰值，需要约 265.974307 μs。
最后一次 N=160+96 的实验没有提升，按用户要求停止试参，恢复最好的
N=128+128 满块特化版本，并在 `Perry` 分支保存代码及本记录。

只验证用户指定的默认 case，不将结果推广为其他形状、mask 或布局的保证。
未修改比较容差、输入规模或 MFU 分母来达成目标。

## 环境与测量口径

- conda 环境：`qmla`；设备：Ascend950PR；CANN 9.1.0。
- CPU 亲和性限制为 10 核；进程树 RSS 以 100 ms 间隔采样，达到 18 GiB 终止。
  容器 cgroup 只读，RSS watchdog 不是 20 GiB 硬限制；本轮构建和精度验证峰值约
  3.27 GiB，性能采集约 2.12 GiB。
- 默认输入：B=1，Q heads=96，KV heads=1，Q length=8，KV length=102400，
  QK dimension=576，V dimension=512，FP8 E4M3 输入，BF16 输出，PA_NZ，mask=0。
- 输入直接在 NPU 生成，默认不保存、不加载 tensor 文件；golden 与比较也在 NPU。
- 只采普通 msprof，不采深度指标或流水图。
- 参照 `ops-transformer-testkit`：每次算子调用前读 256 MiB buffer 刷 L2，
  同步后调用算子。metadata 生成在循环外。
- 预热 5 次，测量 20 次。从 op_summary 只选 `QuantFlashMlaWithKvcache`，
  丢弃前 5 条，剩余 20 条去掉各一个最大值、最小值后取均值。
  表中所有 MFU 均使用该截尾均值，不使用最快样本或中位数替代。
- 有效 FLOPs = `2 * 96 * 8 * 102400 * (576 + 512) = 171127603200`。
- FP8 峰值按此前约定为 `2 * 378.47 = 756.94 TFLOPS`。
- MFU = `effective_flops / (duration_us * 1e-6) / 756.94e12`。

## 最终代码改动

1. **QK/PV matmul 特化**：使用静态 L0 Tensor 和 Mutex，移除通用 MatmulK/MatmulN
   调用及 L0 BufferManager/BuffersPolicy；matmul 内部不再使用逐块 Set/Wait。
   跨核 Cube/Vector 数据交接仍保留必要同步。
2. **QK K=192**：576 维分为三个等长块。默认 M=64、S2=256，内部 N=128+128。
   满块循环展开，交替更新两个独立 L0C 累加区域；尾块保留单独路径。
3. **MTE1/Cube 流水**：L0B 为两个 32 KiB 槽，交替装载与计算。完整 Q 占
   L0A 36 KiB，并在整个当前 Q 块的 S2 循环中常驻；P 占另一个 16 KiB 区域。
   PV 使用四个 N=128、K=256 的基本块，每个 B 块恰好占 32 KiB；P 每轮只加载一次。
4. **S2 从 128 增至 256**：host tiling 与 metadata 同步更新。L1 保留一个 Q 槽
   和三个 KV/P 槽；每个 KV 槽中的最后 64 维在 QK 用完后复用为 P。
   外层调度为 QK(i)、PV(i-1)，保留四个 task 参数槽，避免预取覆盖未消费参数。
5. **256 列 FP8 softmax**：补齐逐行 Q/K 反量化、mask/尾列处理、在线 max/sum、
   P 乘 448 后的 FP8 NZ 输出。公共 256 列分支不具备本路径需要的 MLA 全量化逻辑。
   Q scale 地址每轮正确绑定；单缓冲 P 输出使用对应的槽位取模。
6. **输出更新特化**：FP32 在线累加，在最后一次更新统一执行 V 反量化和归一化，
   减少中间轮次的重复乘法。保留独立的在线 max/sum 后处理；将其融合进 softmax
   的后续实验没有提升，已经撤回。
7. **UB 与 FD 布局**：QK 结果单缓冲、PV 结果双缓冲，调整 P、mask、LSE 和广播
   缓冲容量，同时更新 flash decode 的工作区起点。
8. 增加 `build_and_run.sh`、资源保护、普通性能采集脚本；golden 默认走 NPU、
   避免 GQA 大张量复制；比较按块在 NPU 执行；文件缓存仅通过显式参数启用。

主要源文件位于 `op_kernel/arch35/`，包括 `quant_flash_mla_block_cube_fp8.h`、
`quant_flash_mla_block_vec_fp8.h`、kernel 调度头和 FD 头。

## 复现

在仓库根目录运行：

```bash
QMLA_ALLOW_RSS_WATCHDOG=1 bash attention/quant_flash_mla_with_kvcache/build_and_run.sh all
QMLA_ALLOW_RSS_WATCHDOG=1 bash attention/quant_flash_mla_with_kvcache/build_and_run.sh run --flush-l2 --warmup=5 --runs=20
QMLA_ALLOW_RSS_WATCHDOG=1 bash attention/quant_flash_mla_with_kvcache/build_and_run.sh profile
```

构建脚本同时编译、安装主算子和 metadata 算子，再安装对应 Python 扩展。
每轮 profile 目录包含命令记录、日志和 `performance_summary.json`。
若未来继续优化，建议从本版本出发独立验证新方案，保留相同测量口径，先过精度
再比较性能；本次按用户要求在 N=160+96 退化后停止继续试参。
