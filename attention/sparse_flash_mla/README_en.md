## Description

- Operator function:

  The `SparseFlashMla` operator performs the Attention computation described by the following formula and supports three types of Attention computation scenarios: SWA (Sliding Window Attention), CSA (Compressed Sparse Attention), and HCA (Heavily Compressed Attention). The invocation requires the task list `metadata` generated by `SparseFlashMlaMetadata`.

  The typical invocation flow is as follows:

  1. Prepare inputs such as `q`, `ori_kv`, `cmp_kv`, sequence lengths, `block table`, and `sinks`.
  2. Call `SparseFlashMlaMetadata` to generate `metadata`.
  3. Call `SparseFlashMla` and pass the `metadata` obtained in the previous step to the main operator.

- Formula:

    $$
    O = \text{softmax}(Q@\tilde{K}^T \cdot \text{softmax\_scale})@\tilde{V}
    $$

    Here, $\tilde{K}=\tilde{V}$ is the $KV$ that actually participates in the computation, controlled by input parameters such as ori_kv, cmp_kv, and cmp_ratio.

## Constraints

- This API can be used in training and inference scenarios.
- This API supports aclgraph mode.
- This API supports batch consistency.
- This API currently supports four computation scenarios: the SWA (Sliding Window Attention) scenario passes in only `ori_kv`; the SWA sparse ori_kv scenario passes in `ori_kv`, `ori_sparse_indices`, and `ori_topk_length`; the CSA (Compressed Sparse Attention) scenario passes in `ori_kv`, `cmp_kv`, and `cmp_sparse_indices`; the HCA (Heavily Compressed Attention) scenario passes in `ori_kv` and `cmp_kv`.
- The general specification constraints are as follows:
  - Only KV\_N of 1 is supported, and only D of 512 is supported. The D_kv of `ori_kv` and `cmp_kv` is formed by concatenating nope(448) and rope(64).
  - `cmp_ratio` indicates the compression ratio of `cmp_kv` relative to the pre-compression KV length. When only `ori_kv` is passed in, `cmp_ratio` does not participate in the compressed KV computation and must remain the default value 1. Values from 1 to 128 are supported.
  - The values of `ori_mask_mode`, `cmp_mask_mode`, `ori_win_left`, and `ori_win_right` vary by product model. For details, see the "Product Model Constraints" section.
  - The block_size of PageAttention supports 1 to 1024.
  - The `layout_q` and `layout_kv` combinations support only "BSND"/"BSND", "TND"/"TND", "BSND"/"PA_BBND", and "TND"/"PA_BBND". In non-PA_BBND scenarios, `layout_q` and `layout_kv` must be the same.
  - In the SWA sparse ori_kv scenario, `ori_topk_length` must be passed in. The `ori_topk` of the accompanying Metadata API is the last dimension K of `ori_sparse_indices`, and the element values of `ori_topk_length` must be in the range [0, K]. In other scenarios, pass in nullptr or an empty Tensor for `ori_topk_length`.
- The product model constraints are as follows:
  - <term>Atlas A2 products</term> and <term>Atlas A3 products</term>: Q\_N supports 1, 2, 4, 8, 16, 32, 64, and 128, and KV\_N supports only 1. SWA does not pass in `cmp_kv`, and cmp_ratio does not participate in the computation. CSA supports passing in 1, 2, or 4, and HCA supports passing in 128. block_size must be a multiple of 16, and the maximum supported value is 1024. The SWA sparse ori_kv scenario supports `ori_sparse_indices` and `ori_topk_length`; `layout_q` and `layout_kv` support only the "TND"/"PA_BBND" combination; `ori_mask_mode` is 0; `ori_win_left` and `ori_win_right` are non-negative numbers. In non-SWA sparse ori_kv scenarios, `ori_mask_mode` is 4, `ori_win_left` is 127, and `ori_win_right` is 0. The last dimension K2 of `cmp_sparse_indices` supports any integer in [1, 8192]; `cmp_mask_mode` supports only 3, and topk_value_mode supports only 1.
  - <term>Ascend 950PR&950DT products</term>: Q\_N supports 1-128, and KV\_N supports only 1. When only `ori_kv` is passed in, `cmp_ratio` must be 1. The CSA/HCA scenarios support 1 to 128. `ori_mask_mode` supports 0, 3, and 4, and `cmp_mask_mode` supports 0 and 3. `ori_win_left` and `ori_win_right` support -1 or non-negative numbers, where -1 indicates that the corresponding direction is unlimited. Only when `ori_mask_mode` is 4, `ori_win_left` and `ori_win_right` can be >=0. topk_value_mode supports 1 and 2.

- When `layout_q` is TND, the function usage restrictions are as follows:
  - The shape of `q` must be [Q\_T, Q\_N, D].
  - In the SWA sparse ori_kv scenario, the shape of `ori_sparse_indices` is [Q\_T, KV\_N, K], and the shape of `ori_topk_length` is [Q\_T, KV\_N].
  - The shape of `cmp_sparse_indices` must be [Q\_T, KV\_N, K2], where K2 is the number of tokens selected in a single sparse selection from `cmp_kv`.
  - `cu_seqlens_q` must be passed in, with the shape [B+1,]. The first number is fixed to 0, that is, the prefix 0. Each of the following elements indicates the total number of tokens (prefix sum) of the current batch and all preceding batches. Therefore, the value of each element must be greater than or equal to that of the preceding element.

- When `layout_q` is BSND, the function usage restrictions are as follows:
  - The shape of `q` must be [B, Q\_S, Q\_N, D].
  - In the SWA sparse ori_kv scenario, the shape of `ori_sparse_indices` is [B, Q\_S, KV\_N, K], and the shape of `ori_topk_length` is [B, Q\_S, KV\_N].
  - The shape of `cmp_sparse_indices` must be [B, Q\_S, KV\_N, K2], where K2 is the number of tokens selected in a single sparse selection from `cmp_kv`.

- In the PageAttention scenario, the function usage restrictions are as follows:
  - The shapes of `ori_kv` and `cmp_kv` are [ori\_block\_num, ori\_block\_size, KV\_N, D] and [cmp\_block\_num, cmp\_block\_size, KV\_N, D], respectively, where ori\_block\_num and cmp\_block\_num are the total number of blocks in PageAttention, and ori\_block\_size and cmp\_block\_size are the number of tokens in a block. ori\_block\_size and cmp\_block\_size support values from 1 to 1024, and only KV_N of 1 is supported.
  - The shapes of `ori_block_table` and `cmp_block_table` are 2-dimensional. The length of the first dimension is B, and the length of the second dimension must not be less than the number of blocks corresponding to the maximum S2 and S3 among all batches, that is, the ceiling of ORI\_KV\_S\_max / block\_size and CMP\_KV\_S\_max / block\_size.
- `metadata` is the core splitting result that the operator actually needs to use. This parameter is currently mandatory, and the shape size is fixed to [2048].
- `layout_kv` supports the input "BSND", "TND", and "PA_BBND" values, which must satisfy the preceding `layout_q` and `layout_kv` combination constraints.
  - When the input is PA_BBND, `seqused_ori_kv` and `ori_block_table` must be passed in. When the input is BSND, `seqused_ori_kv` can be used to express the valid length of `ori_kv` in each batch, and the valid length must not exceed KV_S of key/value and must not be less than 0. When the input is TND, the total length of `ori_kv` is expressed by `cu_seqlens_ori_kv`. If `seqused_ori_kv` is passed in, the valid length of `ori_kv` is expressed by `seqused_ori_kv`; otherwise, the valid length is the same as the total length.
  - When the input is BSND, the layouts of both `ori_kv` and `cmp_kv` must be BSND. The shape of ori_kv is [B, ORI\_KV\_S, KV\_N, D], and the shape of cmp_kv is [B, CMP\_KV\_S, KV\_N, D].
  - When the input is TND, `cu_seqlens_ori_kv` must be passed in. If `cmp_kv` exists, `cu_seqlens_cmp_kv` must also be passed in.
- When `return_softmax_lse` is False, a placeholder Tensor is returned. When it is True, the log-sum-exp result of softmax is returned.
- The SWA sparse ori_kv scenario supports only the SWA template. Only `ori_kv` is passed in, and `ori_sparse_indices` and `ori_topk_length` must be passed in together. `ori_win_left` and `ori_win_right` take non-negative numbers only when `ori_mask_mode` is 4. The `ori_topk` of the accompanying Metadata API is K, and `cmp_kv` is not passed in this scenario.
- `ori_topk_length` indicates the actual number of valid index entries for each q token and KV head, and the values must be in the range [0, K]. In `ori_sparse_indices`, the range [0, ori_topk_length) contains left-aligned valid index entries, and the range [ori_topk_length, K) contains invalid or padded entries. It is recommended to fill in -1.
- For unused reserved inputs, they can be omitted or passed in as empty Tensors. Other passed-in Tensors do not support being empty.
- `seqused_cmp_kv` is an optional input for all `layout_kv` values. When explicitly passed in, it is used to overwrite the logical valid length on the cmp side. When it is not passed in, the length is derived from the `cmp_kv` shape, `cu_seqlens_cmp_kv`, or the PA block table semantics.
- `cmp_residual_kv` is an optional input parameter of both the main API and the metadata front-end API. After it is passed in, it is used to restore the pre-compression KV length used by the cmp-side mask as `cmp_len * cmp_ratio + residual`, where `cmp_len` preferentially comes from the explicitly passed-in `seqused_cmp_kv`.
- The data layout formats of `q`, `ori_kv`, and `cmp_kv` can be interpreted from multiple dimensions. B (Batch) indicates the batch size of the input samples. S (Seq-Length) indicates the sequence length of the input samples. H (Hidden-Size) indicates the size of the hidden layer. N (Head-Num) indicates the number of heads. D (Head-Dim) indicates the smallest unit size of the hidden layer, satisfying D=H/N. T indicates the cumulative sum of the input sample sequence lengths of all batches.
- Q\_S indicates the S in the q shape. ORI\_KV\_S indicates the S in the ori_kv shape. CMP\_KV\_S indicates the S in the cmp_kv shape. Q\_N indicates num\_q\_heads. KV\_N indicates num\_ori\_kv\_heads and num\_cmp\_kv\_heads. Q\_T indicates the cumulative sum of the input sample sequence lengths in the q shape.
